# 01 需求

## 1. 用户与场景

| 项 | 内容 |
| --- | --- |
| 用户 | 短视频创作者 / 品牌运营，自己写脚本但没有专职编导 |
| 场景 | 拿到一个产品和一份产品资料，需要在几分钟内产出一条 30 秒左右的种草脚本 |
| 真实痛点 | 1）写快了容易编参数、编效果数据；<br>2）旁白念出来超时长，事后才发现；<br>3）改稿后不知道有没有踩品牌红线 |
| 期望 | 给我一版能直接改的稿子，并且告诉我每条产品事实出自哪份资料 |

## 2. 目标（可验证）

1. 输出结构完整：标题、分镜、旁白/字幕、预计总时长、素材来源 ID、风险、任务状态。
2. **事实可追溯**：旁白里每一条产品事实都能对应到素材 ID，且素材原文支持该表述。
3. **时长可控**：总时长由工具核算（不是模型自报），超出目标时能修正并复检。
4. **异常明确**：缺信息、无素材、工具失败、无法满足约束时，都有明确状态与说明，而不是硬编一版。

## 3. 输入契约

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `topic` | ✅ | 主题，如“露营投影仪怎么选” |
| `platform` | ✅ | `douyin` / `shipinhao` / `bilibili` / `xiaohongshu` |
| `target_seconds` | ✅ | 目标时长（秒） |
| `audience` | ⬜ | 受众 |
| `style` | ⬜ | 风格 |
| `product_ids` | ⬜ | 限定素材检索范围 |

必填缺失时不允许“猜一个”继续生成——这是本题的核心验收点之一。

## 4. 输出契约（`ScriptResult`）

```
status            6 态：completed / completed_with_warnings / needs_input
                        / failed_unfixable / failed_tool_error / incomplete_limit_reached
script.title      标题
script.shots[]    分镜：shot_id、visual、narration、fact_refs
script.disclaimer 免责声明
estimated_total_seconds   来自 estimate_duration 工具，不接受模型自报
fact_map          素材 ID → 原文片段
check             规则检查结果（含违规项）
risks             风险项（含“时长估算误差”）
messages          面向用户的说明（缺什么、为什么失败）
steps / tool_calls 实际消耗
```

## 5. 范围

**做**：单轮生成 + 改稿闭环、素材检索、时长估算、规则检查、执行记录（trace）、离线 Mock、CLI、测试。

**不做**（题目明示非必需，且 3 小时预算内会稀释核心链路）：

- 图形界面、线上部署、账号体系；
- 多 Agent 协作、生产级 Runtime、持久化记忆；
- 向量检索（关键词检索足够，且更容易构造“无结果”场景做验收）；
- 真实视频渲染、配音、素材版权校验。

## 6. 成功标准（对应验收点）

| # | 验收点 | 判定标准 |
| --- | --- | --- |
| A1 | 正常生成 | `status=completed`，分镜 ≥3，时长在目标 +1s 容差内，每条 `fact_refs` 都能在已检索素材中找到 |
| A2 | 缺关键信息 | `status=needs_input`，列出缺失字段，不产生脚本 |
| A3 | 无素材 | 检索 0 命中后**改写查询**（≥2 次且查询不同），仍无结果则请求补充，不编造 |
| A4 | 工具失败 | 失败被观察并写入 trace，模型改变动作（换参重试 / 降级 / 终止），流程不崩 |
| A5 | 超时长 | 首稿超目标 → 压缩 → **再次估算** → 进入容差；若多轮仍不行则 `failed_unfixable` 并说明原因 |
| A6 | 达到上限 | 步数/工具调用/改稿轮数任一触顶 → `incomplete_limit_reached`，并附当前进度 |
| A7 | 防编造 | 无素材依据的断言、素材中不存在的数字、百分比效果数据 → 规则检查拦截 |
